Status correction, 2026-11-14: section C was mislabelled, and four cards have since been attached. Its nine rows were tagged done with commit fcc62b3. That commit installed the capabilities as dependencies. None of them is attached to any agent: PromptInjectionDefender, ArtifactScanning, DetectLoops, ModelFallback, Caching, AskUser, Permissions, ApprovalReviewer, ToolCallJudge, TrajectoryJudge, SmartSearch, IPythonCodeMode and CapabilityCreation all return nothing when grepped across src/autfin/. Their tag is now INSTALLED and their boxes are unchecked, so the document matches the repository.
Decisions recorded, so they are not re-litigated: workspace capabilities are dropped entirely - 2.68 requires an attached workspace, LocalWorkspace is POSIX-only and DockerSandbox hard-codes that same POSIX runner on the client, so Windows has no supported local workspace. No agent exposes file/workspace/shell tools, so nothing was lost (upstream: pydantic-ai#9873). browser-use is uninstallable (it pins pydantic==2.12.5).
Next: phase 4 has three capabilities left that are still only dependencies - SmartSearch, IPythonCodeMode and CapabilityCreation - none of which the repo's toolset needs today (quant already covers sandboxed compute with CodeMode). After that, section B's three open items: B15 WarnOnCacheBusts (attached), B16 prompt caching (attached but measured as a no-op on NIM), and B17 XSearch, the one feature with a real content gap - the social half of get_sentiment_data.

Project plan

PHASE 1

Requirements and scope

COMPLETE

What the migration must deliver, and the constraints it is bound by.

In scope. Replace every hand-rolled subsystem that the framework now owns, and attach the capabilities the upgrade unlocked, so that one agent graph carries its guardrails, its cost ceilings, its crash recovery, its history bounds and its traces through the framework rather than through local code. Verified live, not only by construction: the supervisor and a sub-agent both complete a real run on NIM.

Out of scope, by decision. Workspace and file/shell capabilities (no local workspace exists on Windows, and no agent needs one) · paid research providers (Exa, You.com) · a durable workflow engine · serving an editor client.

Acceptance. uv run pytest tests/ -q green · the checklist on this page matches the code when grepped · every decline and every block carries its measured reason and the trigger that would reopen it · AGENTS.md and autfin-architecture.html updated in the same commit as the change they describe.
